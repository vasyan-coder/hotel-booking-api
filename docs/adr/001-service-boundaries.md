# ADR 001: границы сервисов и данные

Статус: принято.

Booking Service владеет пользователями, аутентификацией и состояниями бронирований. Hotel Service владеет каталогом, операционной доступностью и календарём занятости. У каждого отдельная H2 in-memory БД. Общие таблицы, межсервисные SQL-запросы и глобальные транзакции отсутствуют.

Календарь Hotel — локальная проекция бронирований (`room_reservations`), позволяющая атомарно проверить пересечения и занять номер. Внешний ключ между базами не используется: `room_id` и `booking_id` — идентификаторы интеграционного контракта.

Gateway и Eureka не хранят бизнес-данные, поэтому отдельные пустые H2 для них не создаются. Common — библиотека, а не пятый микросервис.

Последствие требования H2 in-memory: перезапуск очищает данные. Запускать демонстрационный стенд следует целиком; независимый перезапуск одного сервиса может нарушить соответствие проекций. Для постоянной эксплуатации нужны постоянные БД, миграции и процедура восстановления проекций. Это осознанное ограничение учебной конфигурации.
