# ADR 003: конкурентное распределение номеров

Статус: принято.

Интервалы полуоткрытые: `[startDate, endDate)`. День выезда не занимает ночь; заезд другого гостя в этот день разрешён. Пересечение существует, если `existing.start < requested.end AND existing.end > requested.start`.

Автоподбор выбирает доступные по датам и операционному флагу `available` номера одного отеля в порядке `times_booked ASC, id ASC`. Счётчик увеличивается ровно один раз после успешного выделения и сохраняет историческое число выделений после отмены. Это детерминированная, проверяемая статистика; прогнозирование спроса не используется.

Перед проверкой и изменением календаря транзакция блокирует строку отеля `PESSIMISTIC_WRITE`. Операции размещения и освобождения в одном отеле сериализуются на уровне БД; разные отели работают независимо. Это обеспечивает отсутствие двойного размещения и согласованный выбор минимального счётчика. Ограничение: один очень крупный отель становится точкой конкуренции; для учебного стенда корректность предпочтительнее сложных распределённых блокировок.

Терминальные записи освобождения сохраняются для идемпотентности. Их нельзя удалять до окончания согласованного срока повторной доставки.
