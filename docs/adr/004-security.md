# ADR 004: проверка токенов и внутренние операции

Статус: принято.

JWT проверяется в Gateway и в каждом бизнес-сервисе: подпись HS256, срок, issuer и audience. Пользовательский токен действует один час. Пароли хранятся как BCrypt-хеши, регистрация не позволяет назначить себе ADMIN.

Роли USER и ADMIN ограничивают публичные операции через Spring Security и `@PreAuthorize`. Для интеграции Booking выдаёт токен на один час с ролью INTERNAL. Этот токен не выдаётся через пользовательские эндпойнты. Hotel требует INTERNAL для выделения и освобождения слота; Gateway блокирует эти маршруты независимо от роли.

Секрет общий для доверенных сервисов и задаётся через окружение. Для эксплуатации за пределами локального стенда предпочтительны отдельный issuer с асимметричными ключами, ротация ключей и TLS. Eureka — компонент доверенной внутренней сети; его протокол регистрации не требует пользовательского JWT.

Обновление роли отражается в новом токене. Stateless JWT не отзывается мгновенно; срок жизни ограничивает окно действия. Booking дополнительно проверяет существование пользователя при создании бронирования.
